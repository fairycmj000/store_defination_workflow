# 门店定义数据加工（指定客户类型关联 + 清洗去重）

两步加工，输出独立新文件（默认到 `输出文件\`，不覆盖原输入）：

1. **关联**：`join_designated_customer.py` —— 把「指定客户城市总部.xlsx」的「指定客户类型」按客户编码关联进输入文件最后一列。
2. **清洗 + 去重**：`clean_store_type.py` —— 关联指定客户类型 + 清空与店型判断无关的字段取值 + 按店型判断条件列去重。

## 关键口径（先看，易踩坑）

- **关联键**：A 的「二级城市总部编码」 = B 的「客户编码」。
- **「全国总部编码」≠ 单独一列**：口语里的「全国总部编码」在文件里就是「二级城市总部编码」。B 的「客户属性」虽然全是「全国总部」，但其「客户编码」落在 A 的二级城市总部这一层；「一级/三级城市总部编码」与 B 的客户编码 0 匹配，用了会整列 `#N/A`。
- A 若已带「指定客户类型」列（旧文件里是 `#N/A` 残留），脚本会覆盖其值；若没有该列，脚本自动追加为新列。
- A 的 Sheet2（渠道维度汇总，无城市总部编码列）不参与关联，脚本只处理 Sheet1。若输入文件只剩 Sheet2、没有 Sheet1，说明抽数少了「按城市总部维度」那张，需重新抽数。
- B 的 sheet 名是小写 `sheet1`。

## 店型清洗去重口径（2026-10-24 与用户逐步确认）

依据飞书文档「3.1.1.4 渠道类型计算逻辑更新」的店型计算脑图：店型 = 渠道 + 商圈 + 特征 + 城市总部 四维 + 若干子判断条件。

- **保留列（17 列，全部参与去重）**：
  - 渠道编码/名称（一级渠道编码/名称、二级渠道名称、三级渠道名称）——判断条件组合得到的**结果列**，用户明确要求也加入去重；
  - 门店判断条件：商圈环境名称、门店特征、是否生鲜主导、是否大宗售卖、收银机个数、门店营业面积、进口产品SKU超40、营业时间超16小时；
  - 店型判断条件三类：传统渠道店型判断条件、O2O店型判断条件、批发渠道类型（WS 批发店型的判断条件）；
  - 城市总部是否连锁；
  - 指定客户类型（关联步骤写入）。
- **删除列（全局不参与店型计算，9 列，直接不输出）**：一级/二级/三级城市总部编码/名称（6 列）、KA类型编码、RTM渠道名称、有效门店数。
- **去重键** = 上面 17 个保留列全部相同才合并成一行。
- **指定客户类型 值级清空**：每个指定客户类型值只对其目标店型有效（如 高端便利店客户 只对 高端便利店 有效），出现在其它店型里则清空（见 `clean_store_type.py` 的 `CUSTOMER_TYPE_STORE`）。
- **OR 条件互斥**：店型由多条「任一满足即可」的独立条件判定时，各行只保留命中的那一条（如 仓储式卖场 = 指定客户类型=仓储式卖场客户 或 是否大宗售卖=1，见 `OR_CONDITIONS`）。
- **条件字段清空**：某字段仅在特定取值下参与判定，其余取值时清空（如 校园内小型超市 大面积 70-500/500-1200 时 连锁 无关 → 清空，见 `CONDITIONAL_CLEAR`）。
- **连锁归一化**：**连锁=空 等同 连锁=否（0）**，值级统一输出 0/1（`_chain_num`），去重合并「空」与「0」；**「连锁*」「便利店」店型要求 连锁=是**，空/否即脏数据剔除。
- **校园店分层**：商圈=校园（高校/中小学）时按面积分层——面积 1200-6000/＞6000 → 校园内标准超市、面积 70-500/500-1200 → 校园内小型超市（连锁无关）；面积 40-70/＜40 才看连锁：连锁=0 → 校园内TT店、连锁=1 → 校园内小型超市。
- **已知数据缺口占位行**：源数据缺「校园-中小学校园内 + 面积＞6000㎡」的校园内标准超市组合（决策树本应存在），去重后手工补一条占位行（见 `clean_store_type.py` 的 `SYNTHETIC_ROWS`），源数据补抽后可删除。
- **脏数据剔除（去重前）**：按店型「必备条件」剔除不满足的整行（不作为有效条件）——如 折扣店/自营式前置仓 指定客户类型空、生鲜店 生鲜主导非「是」、大众便利店 营业时间未超 16h 或连锁非「是」、连锁小型超市 连锁空、区域连锁零食客户 连锁非「是」、校园内TT店 连锁非「否」或面积非小档 等（完整规则见 `clean_store_type.py` 的 `MANDATORY`）。
- **注意**：「传统渠道店型判断条件」「O2O店型判断条件」列名带「店型」，但实际存的是**判断条件**（如「传统渠道店型判断条件」存的是 食杂/烟酒售卖区域>50% 等），按判断条件保留、参与去重。
- **输入前置**：输入文件须已包含「是否大宗售卖」「批发渠道类型」两列（2027 新口径新增）；缺失时脚本报错提示补入。

## 怎么跑

```bash
# 一步到位：关联 + 清洗 + 去重
python "D:/CMJWORK/业务知识库/自动化工具/designated-customer-type-join/scripts/clean_store_type.py"

# 只做关联（不清洗去重）
python "D:/CMJWORK/业务知识库/自动化工具/designated-customer-type-join/scripts/join_designated_customer.py"
```

无参数时，自动取输入目录下日期最新的一份 `生产门店数据_By条件汇总_*.xlsx`（按文件名尾部的日期数字排序，如 1024 > 1023）。也可显式指定输入文件：

```bash
python clean_store_type.py --input "…/输入文件/生产门店数据_By条件汇总_1024.xlsx"
```

## 参数（clean_store_type.py）

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--input` | （空=自动取最新） | 输入文件 A 路径；不传则取输入目录下日期最新一份 |
| `--input-dir` | 输入目录 | `--input` 缺省时在此自动找 `生产门店数据_By条件汇总_*.xlsx` |
| `--deps` | 依赖文件 B 路径 | 指定客户城市总部 |
| `--output-dir` | 输出目录 | 独立输出，不覆盖输入 |
| `--sheet-a` | Sheet1 | 要处理的工作表 |

## 执行步骤 & 校验

1. 跑前核对输入文件：是带「二级城市总部编码」的 Sheet1，且已含「是否大宗售卖」列。
2. 跑 `clean_store_type.py`，看 stdout：`[输入] 自动取最新: …` 显示选中哪个输入；`[脏数据] 剔除 X 行…`（店型必备条件不满足）；`[A] 去重前 N 行，去重后保留 M 行，删 K 行`。
3. 抽查输出文件：指定客户行有类型值、全局无关列（城市总部编码/名称 3 级 / KA类型编码 / RTM渠道名称 / 有效门店数）已不输出、无 `#N/A`。
4. 确认原输入文件未被改动（脚本只写输出目录）。
