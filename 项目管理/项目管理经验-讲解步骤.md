# 项目管理经验同步会 · 讲解步骤（45–60 分钟）

> 现场提词卡，配合 `项目管理经验.html` 使用。主线：**7 个管理对象**；文稿骨架 = 管理对象 × 项目阶段 × 管理内容 × 管理方式（工件橙 / 活动组织紫 / 个人行动项玫红 / 交付物金）。

## 讲解目的（开场第一句话的底稿）

**一句话目的**：把 2026 COT 系统升级沉淀下来的「对象 × 阶段 × 内容 × 方式」这套管理方法，以高层框架的方式同步给团队，让明年同类项目能直接复用。

两个具体目标：

1. **对齐认知** —— 统一「项目管理到底管什么、用什么管」的框架语言，让听众拿到同一张地图。
2. **可复用交接** —— 交付一份能照着用的参考手册：每个对象「管什么 → 用什么管 → 怎么构件」三段式，接手人可逐节套用。

## 讲前准备（5 分钟内做完）

1. 浏览器打开 `项目管理经验.html`，确认思维导图可点、节点右侧 −/＋ 可折叠、正文文件名可下载。
2. 按 ③–⑨ 顺序预开一遍要演示的文档（都已在 HTML 内嵌，点即下载，无需本地路径）。
3. 把 13 条经验要点在心里过一遍（对应行号见各步标注）。

## 分步详解

### ① 开场 · 这份手册是什么（3 min）

- **先亮目的**：一句话目的 + 两个目标（对齐认知 / 可复用交接），见上文「讲解目的」。
- 一句话定位：**这是一份可复用参考手册，不是 2026 项目流水账**——抽象成「管什么、用什么管、怎么构件」，供明年同类项目接手时直接复用。
- **基调**：高层框架为主——每个对象讲「管什么 → 用什么管 → 怎么构件」三段，13 条经验要点只作一句话收口、点到为止，不展开具体踩坑细节。
- 念 header 三行 meta（用途 / 参考源 / 关联个人行动指南），点明「新人接手 + 经验分享」双用途，覆盖混合听众。
- 念「声明 · 全文范围」：本文讲**全盘了解**（对象×阶段×内容×方式），不含各任务项行为准则——先划清边界，避免被追问到过细规范。

### ② 全景框架 · 一页看懂（5 min）

- 放出整张思维导图，先讲**根 + 7 个顶层对象**（需求范围 / 人 / 任务项 / 进度 / 成本 / 质量 / 文档）。
- 讲四维度：**对象 → 项目阶段（启动→分析→开发→验收→上线→Hypercare→项目收尾）→ 管理内容 → 管理方式**。
- 讲「贯穿全程」：项目甘特图 / 周报 / 项目进度表 / 变更风险管理表 / 工时登记，跨阶段工件不归某一个阶段。
- **现场演示交互**：点一个容器节点右侧 −/＋ 折叠再展开，展示布局自适应收缩/扩张；点一个橙色工件节点展示直接下载。说明图例 6 类（绿=对象/内容、蓝=阶段、橙=工件、紫=活动组织、玫红=个人行动项、金=交付物）。

> 这是「导航地图」，先给坐标轴，后面 7 个对象往里填内容。

### ③ 对象 1 · 需求范围（6 min）—— 需求从粗到细收敛 + 变更受控

- 讲骨架：**BRD → Work Stream（A–E 五类）→ PRD CheckList** 逐级收敛；Work Stream「类+序号」编号是全局主键，WBS/CheckList/测试用例都挂同一编号。
- 讲两个工件：需求基线（BRD→Work Stream→PRD CheckList）、变更风险管理表。
- **演示**：点开 BRD（docx）看「影响面如何一次性点全」（附录 + 下游系统清单）；点开项目进度主档里的 PRD CheckList 原格式还原表，看列结构（编号 / Work Stream / PRD 分类 / 版本 / UI / BA / Sign off / 评审状态）。
- **收口经验要点（3 条）**：
  - BRD 只签「为什么/做什么/何时上」，但影响面必须一次点全（漏在 BRD 影响面外的下游系统会漏改）。〔行 368〕
  - 欠项要「显性化」：待业务提供清单用「跟进人 + 最晚时间 + 双状态」钉死，超期可升级。〔行 432〕
  - 变更不口头答应，一律「登记 → 评估成本 → 排期」。〔行 435〕

### ④ 对象 2 · 人（5 min）—— 团队分工 + 人员时间安排

- 讲组织结构 4 团队（需求分析·开发 / 质量管理 / 项目管理 PM+助理PM）+ 项目整体要求（对外留痕、对内同步、进度更新 WBS、变更走流程、角色质量负责）。
- 讲人员时间安排：BA 按周列并行占用、开发按项目/人员/周人天、SIT 与 BA 共用同一 Sheet、UAT/hypercare 按测试入口固定投入。
- **演示**：点开 BA 人员时间安排 / 开发人员时间安排两个 Sheet（batime/devtime），看「按周登记占用」。
- **收口经验要点**：关键人要按周登记时间占用防过载，避免同一份资源被两个计划重复承诺。〔行 445〕

### ⑤ 对象 3 · 任务项（7 min，全篇最大）—— 全链路任务编排

- 讲六段链路：**整体（甘特图）→ 需求分析（PRD CheckList）→ 开发（WBS）→ 测试（SIT/UAT/联调）→ 上线部署（部署计划）→ Hypercare（保障计划）**。
- 讲 WBS 层级骨架 `TK-A 分析与设计 → TK-A1《BRD》sign-off → TK-A2《PRD》编写/评审/sign-off → 子项`，每行落到负责人 + 预估/实际工时 + 验收人。
- **演示**：点开项目进度主档里的**项目甘特图（原格式还原）**看阶段×周全景；点开 WBS 看编号骨架；点开部署计划看分区结构（计划 / 准备 / 保障 / 各系统上线项）。
- **收口经验要点（2 条）**：
  - 任务编号即进度单元，编号与 Work Stream / PRD CheckList 同源，跨表对账不串位。〔行 653〕
  - UAT 前先挡「超前测试」：issue log 同时登记「现象归类/问题领域/问题原因/调查记录」，先把「是缺陷还是未到交付窗口」分清，避免拿超前环境问题空转。〔行 656〕

### ⑥ 对象 4 · 进度（4 min）—— 对外 / 对内双通道

- 讲两条通道分用：**对外（客户可见）= 周报 + 周例会固定节奏**；**对内 = 飞书公告 + 在线文档实时更新**。
- **演示**：点开项目周报（weekly），看 Overall Status（On Track / Low Risk / High Risk）+ 分阶段 + Critical Issues 结构。
- **收口经验要点**：关键风险（PRD sign off 延迟、IR 识别率低需重训）要进 Critical Issues 显性升级，不埋在对内文档里。〔行 701〕

### ⑦ 对象 5 · 成本（4 min）—— 预算基线 + 工时

- 讲报价三层收敛：**high level → 终版 → 变更项**，变更项单独计价、与范围变更同表联动。
- **演示**：点开报价 v3（quote），看「人天 + 总价（税前/税后）」分项登记的结构。
- **收口经验要点**：报价逐版收敛既控预算基线，又给后续贡献度评定提供工时依据。〔行 709〕

### ⑧ 对象 6 · 质量（6 min）—— 四道评审门禁

- 讲四道门禁：**PRD review 会议组织 → PRD 评审 + PRD BUG 登记 → 技术方案评审 → 测试用例评审**；UAT Sign off 是上线放行条件。
- 讲活动组织（紫）与工件（橙）的区别：评审会议是「活动组织」，测试用例 check list / BUG 登记是「工件」。
- **演示**：点开测试用例 check list（tccl），看「按业务团队 × 测试入口列谁验收、什么内容、何时 Sign off」。
- **收口经验要点**：PRD BUG 登记把评审发现的歧义逐条确认闭环，避免带病进开发；UAT Sign off 是放行红线。〔行 715〕

### ⑨ 对象 7 · 文档（4 min）—— 三分类归档 + 交付物索引

- 讲三分类：**业务类（PRD、测试用例/报告）/ 技术类（服务架构图、网络拓扑、接口文档）/ 项目管理类（WBS、周报、部署计划）**。
- 讲「交付物」单独标金：PRD 文档、测试用例/报告、issue log、接口文档、服务架构图、网络拓扑图——既是交付清单，也是接手人快速定位「这项目产出了什么」的索引。
- **演示**：点开产品中心接口整理（iface）看技术归档样例。
- **收口经验要点**：三分类归档 + 交付物索引 = 接手人的第一张地图。〔行 718〕

### ⑩ 收尾 · 上线→交接 + 附录（5 min）

- 一句话带过一 章「项目筹备及启动」：启动会「介绍人 + 讲清范围 + 给出时间表」一次对齐，backlog 启动前就要有初版。〔行 363〕
- 讲三章「项目收尾」：**上线部署 → Hypercare → 对外/对内双交接** + SV 平台上下架报表清单。
- **收口经验要点（2 条）**：
  - 上线窗口一次讲清「停服范围 + 影响面 + 恢复时点」，部署计划保证可编排、可回退。〔行 726〕
  - 收尾 ≠ 上线即结束；Hypercare→常规运维双交接提前约定窗口与升级路径；复盘 + 贡献度评定是激励与复用抓手。〔行 734〕
- 翻到附录「关键文件清单」宽表，给 16 个内嵌文件的全局一张图（xlsx / pptx / docx 均已内嵌、可直接下载）——这是会后「带走什么」的总入口。

### ⑪ Q&A（5–10 min）

- 预判会被问的：每个工件模板怎么填、明年能不能直接套、哪些是 2026 特有 vs 可通用。回答口径：**「表结构/列/层级 = 可复用骨架，具体数值 = 2026 示范」**。
- 引导到附录清单 + 思维导图节点，让提问者会后自己点开对应工件。
